# chicchicpokpok

전국 기차역 지도와 열차 경로를 탐색하는 기차여행 웹서비스 🚂

PC에서는 검색 패널과 지도를 나란히, 모바일에서는 지도와 펼칠 수 있는 하단 패널로 기차역을 탐색합니다.

처음에는 서울 지역의 역을 보여줍니다. 전국 보기에서는 지도를 확대한 뒤 현재 화면의 역을 표시하며, 지도 표시 수는 최대 40개로 제한합니다. 역 이름을 입력하면 전국 검색으로 시작하고 지역 필터로 좁힐 수 있습니다. 목록은 12개씩 추가로 불러옵니다.

기본 지도에는 전체 운행 경로를 그리지 않습니다. 연결 경로를 검색하면 해당 경로와 그 경로의 역만 표시합니다. 긴 역 소개는 접어 두고 필요한 경우 펼쳐 읽을 수 있습니다.

수집 데이터에서는 실제 열차편별 정차 순서와 한국시간 출발·도착 시각으로 경로를 계산합니다. 시각이 역전되거나 형식이 잘못된 열차편은 검색에서 제외합니다. `적은 환승`은 환승 횟수를 먼저, 같은 횟수에서는 도착 시각을 비교합니다. `빠른 도착`은 요청 시각 이후 가장 빨리 도착하는 편을 비교하므로 직통보다 빠른 환승편이 먼저 나올 수 있습니다. 최대 2회 환승과 최소 환승 여유(10·20·30분)를 확인합니다. 열차 선택에 따라 해당 편의 모든 여객 정차역을 표시하며 열차번호·구간별 색상을 지도와 목록에 함께 표시합니다. 오송 등 중간 정차역은 열차마다 다를 수 있습니다. 차종은 공식 필드가 있을 때만 표시하고 없으면 `차종 미제공`으로 안내합니다.

## 현재 제공하는 기능

- 이름·지역 검색, 지역 필터, 기차역 선택
- 브라우저에 저장되는 즐겨찾기
- 출발역·도착역·출발 시각 선택, 열차편 선택, 전체 정차역과 환승 대기시간 표시
- 빠른 도착 / 적은 환승 정렬 선택
- 연결 경로·여행지 추천의 열차 종류 선택: 전체 / 고속열차 / 일반열차, 실제 수집된 세부 차종 복수 선택, 차종 미확인 포함 여부. 환승의 모든 구간과 당일 귀가편에 같은 조건을 적용하며 추천에서 경로 보기로 이동해도 유지
- 출발 지역·역 기반 여행지 추천: 편도 2·3·4시간, 직통 또는 환승 1회 조건으로 전체 지역을 확인하고 8개씩 표시
- 당일 귀가편 확인: 같은 출발역으로 돌아오는 실제 기록, 현지 체류 2시간 이상·23시까지 귀가 조건
- 차종에 맞는 코레일·SRT 공식 예매 페이지 연결. 차종 미제공 시 두 사이트를 안내하며 여행 날짜·좌석은 공식 사이트에서 다시 선택
- Kakao Maps 연동. 키가 없거나 지도 로딩에 실패해도 철도망 미리보기로 탐색 가능

**로컬 기본 데이터는 31개 역·4개 방면의 예시입니다.** 배포 Actions는 승인받은 세 API에서 역과 운행기록을 수집·검증한 뒤 수집 데이터로 빌드합니다. 화면에 데이터 조회일을 표시합니다. 배포본은 해당 날짜 운행 기록에 존재하는 열차만 연결하며, 자료를 불러오지 못하면 임의의 그래프 경로로 대체하지 않습니다. 과거 운행 기록은 실시간 정보나 미래 예약 가능 시간표가 아니며, 실제 환승 동선·좌석·운행 변경은 코레일에서 확인해야 합니다. 샘플 모드에서만 예시 그래프를 사용합니다.

## 개발·운영 비용 원칙

AI 도구 이용료를 제외한 추가 개발·운영 비용 **0원**을 필수 조건으로 유지합니다. 기능 추가 시에도 아래 조건을 따릅니다.

- 공개 저장소의 GitHub Pages와 표준 Linux GitHub Actions 실행기를 사용합니다. 유료 실행기·별도 서버·유료 DB·유료 도메인·유료 분석 서비스를 도입하지 않습니다.
- 공공데이터 API와 Kakao Maps·장소검색은 해당 앱에 제공된 무료 이용 범위 안에서만 사용합니다. 한도 소진 시 기능 제한이나 데이터 갱신 중단을 허용하며, 유료 서비스로 자동 전환하거나 결제·충전·유료 쿼터 확대를 활성화하지 않습니다.
- 경로·추천 검색은 배포된 정적 자료를 재사용합니다. 방문자의 검색마다 공공데이터 API나 장소검색을 호출하지 않습니다. 지도 SDK를 불러오지 못하면 기존 철도망 미리보기를 사용합니다.
- 현재 워크플로는 `main` 변경 또는 수동 실행으로만 수집·배포하며 정기 실행은 없습니다. 수집 요청 수 제한을 유지하고, 한도 오류를 피하기 위한 무한 재시도나 앱·키 우회는 추가하지 않습니다.
- 계정 전체의 사용량과 과금 여부는 브라우저 코드만으로 보장할 수 없습니다. Kakao·GitHub 콘솔에서 무료 이용 조건과 유료 사용 설정을 확인해야 하며, 앱 내부의 캐시나 요청 수 제한을 계정 과금 차단 장치로 간주하지 않습니다.

사용자가 이 예산 조건을 명시적으로 변경하기 전에는 비용이 발생하는 구성을 추가하지 않습니다.

## 개발 환경

Node.js 24와 npm을 사용합니다.

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

개발 주소는 `http://127.0.0.1:5173/chicchicpokpok/`입니다. Vite의 `base`는 GitHub Pages 프로젝트 경로인 `/chicchicpokpok/`으로 설정되어 있습니다.

```bash
npm test       # 수집 무결성, 실제 편별 정차·방향·환승·자정 처리, 정적 자료 캐시
npm run lint
npm run build  # TypeScript 검사와 배포용 번들 생성
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

## Kakao Maps 연결

1. [Kakao Developers](https://developers.kakao.com/)에서 앱을 만들고 카카오맵 사용 설정을 켭니다.
2. Web 플랫폼의 허용 사이트에 개발 시 사용하는 `http://localhost:5173`, `http://127.0.0.1:5173`과 실제 배포 사이트의 origin을 등록합니다. GitHub Pages는 `https://<저장소 소유자>.github.io`를 등록합니다.
3. 클라우드 환경 설정에서 `VITE_KAKAO_MAP_APP_KEY`에 **JavaScript 키**를 입력합니다. 로컬에서는 `.env.example`을 참고해 무시되는 `.env.local`에 설정할 수 있습니다.
4. 개발 서버를 다시 시작합니다. 배포 빌드에는 빌드할 때 변수가 제공되어야 합니다.

이 변수는 브라우저 번들에 포함됩니다. Kakao의 JavaScript 키만 사용하고 REST API 키나 Admin 키는 넣지 않습니다. JavaScript 키의 사용 범위는 Kakao 콘솔의 허용 사이트로 제한합니다. 참고: [Kakao Maps 시작하기](https://apis.map.kakao.com/web/guide/).

## GitHub Pages 배포

`.github/workflows/pages.yml`에 빌드·검사·배포 워크플로가 있습니다. 이 파일을 추가하는 것만으로 사이트가 게시되지는 않습니다.

1. 저장소의 **Settings → Pages → Source**에서 **GitHub Actions**를 선택합니다.
2. 실제 지도를 사용할 경우 **Settings → Secrets and variables → Actions → Variables**에 `VITE_KAKAO_MAP_APP_KEY`를 추가합니다. 클라우드 환경 변수는 GitHub Actions에 자동 복사되지 않습니다.
3. **Actions → Secrets**에 공공데이터포털의 공통 인증키를 `DATA_GO_KR_SERVICE_KEY`로 등록합니다. 철도역 정보·열차운행정보·TAGO 열차정보의 활용신청 승인이 각각 필요합니다. 이 키는 Vite에 전달하지 않습니다.
4. 변경을 `main`에 반영하거나 Actions에서 **Deploy GitHub Pages**를 직접 실행합니다. 수동 실행의 `data_date`에는 `YYYYMMDD`를 지정할 수 있으며 기본 조회일은 한국시간 전날입니다. 조회 결과가 없으면 제공되는 날짜를 확인해 다시 실행합니다.

데이터 수집이나 검증이 실패하면 새 배포를 중단합니다. GitHub에 저장된 인증키는 이 클라우드에서 조회하지 않습니다. 실제 API 인증·최신 응답 형식·날짜별 데이터 제공 여부는 첫 Actions 실행으로 확인해야 합니다.

기본 주소는 `https://<저장소 소유자>.github.io/chicchicpokpok/`입니다. 현재 선택된 저장소 이름 `ImDongHo/chicchicpokpok` 기준으로는 `https://imdongho.github.io/chicchicpokpok/`이며, `imtongho1` 계정의 주소를 사용하려면 저장소도 해당 계정 소유여야 합니다. 배포 성공 여부는 저장소 Actions에서 확인합니다.

## 데이터 교체

`scripts/collect-railway-data.mjs`는 다음 API의 전체 페이지를 수집합니다.

- 국가철도공단\_철도역 정보: ODCloud `15067652/v1`, 2025-07-11 버전. 역 이름·좌표·주소를 사용합니다. [공식 명세](https://infuser.odcloud.kr/oas/docs?namespace=15067652/v1)
- 국토교통부\_(TAGO)\_열차정보: `https://apis.data.go.kr/1613000/TrainInfo`의 `GetVhcleKndList`, `GetCtyCodeList`, `GetCtyAcctoTrainSttnList`, `GetStrtpntAlocFndTrainInfo`를 사용합니다. 같은 날짜·열차번호·역과 운행계획의 예정 출발·도착 시각이 모두 일치하는 경우에만 공식 차종명을 연결합니다. 운행계획이 없는 경우에는 기록 시각의 정확한 일치를 요구합니다. 지연 등이 반영된 운행기록 시각은 경로 목록에 그대로 보존하며 차종 대조용 예정 시각과 섞지 않습니다. 매칭되지 않는 편의 차종을 열차번호 범위로 추정하지 않습니다.
- 한국철도공사\_열차운행정보: `https://apis.data.go.kr/B551457/run/v2`의 `travelerTrainRunPlan2`, `travelerTrainRunInfo2`. 조회일을 하나로 고정하고 역 필터 없이 운행계획과 정차정보를 수집합니다.

발급받은 키가 환경에 안전하게 제공된 경우 `npm run data:collect`로도 실행할 수 있습니다. 선택적 `RAILWAY_DATA_DATE`는 `YYYYMMDD` 형식입니다. 로그에는 인증키나 인증 URL을 출력하지 않으며 TLS 검증을 유지합니다.

수집기는 총 건수·페이지 반복·조회일·스키마를 검증합니다. 동일 날짜·열차의 출발/종착 코드가 운행계획과 일치하고 정차 순서가 완전한 열차를 보존합니다. 누락·중복 순서가 있는 편은 제외합니다. 좌표가 없거나 역명이 모호해도 원본 역 코드와 전체 정차 목록을 보존하고 지도 위치만 미확인으로 처리합니다. 지도는 위치가 확인된 역 사이를 이어 그리며, 위치 미확인 중간역이 있는 구간은 옅은 참고선으로 구분합니다. 미확인 역의 좌표나 마커를 임의로 만들지 않습니다. 유효한 열차가 하나도 없으면 배포를 중단합니다. 최신 API가 필드명이나 순서 의미를 바꾸면 명세를 확인해 수집기를 수정해야 합니다.

생성 결과는 무시되는 `src/data/generated/railway.json`과 `public/data/railway/services-<날짜>-<내용해시>.json`(호환용 `trips.json` 포함)입니다. 경로 또는 추천 탭을 처음 열 때 정적 운행 자료를 한 번 불러와 메모리에 인덱스를 만들고 이후 검색은 이를 재사용합니다. 검색마다 공공데이터 API를 호출하지 않습니다. 내용 해시가 빌드와 자료의 버전 혼합을 방지하며, 자료 로드 실패 시 재시도할 수 있습니다. 배포 전에 `npm run data:validate`가 각 원본 열차편의 정차 목록 보존·방향·환승 시간을 검사하고 대표 구간 결과를 `public/data/railway/validation.json`에 기록합니다. 수집 결과가 있는 빌드는 `src/data/railway.ts`를 통해 해당 데이터를 사용합니다. 생성 파일이 없는 로컬 개발은 `src/data/sample-railway.ts`의 예시를 사용합니다. `src/lib/timetable.ts`가 수집 데이터의 날짜·시각 기반 경로를 계산합니다. `src/lib/railway.ts`의 연결 그래프는 로컬 샘플 전용입니다. 지도 점선은 정차역 사이의 직선 연결이며 실제 선로 형상을 나타내지 않습니다. 이 구분은 실제 지도와 미리보기 모두에서 안내합니다. 한국철도공사 운행기록에는 차종 필드가 없어 TAGO의 같은 날짜 시간표로 교차 확인합니다. TAGO 조회는 빌드 시 수행하고 브라우저에 인증키를 전달하지 않습니다. `public/data/railway/tago.json`에는 인증정보를 제외한 날짜별 공식 시간표를 보존하며, 매칭 근거는 각 열차의 `timetableVerified` 필드에 기록합니다. 다른 날짜의 차종을 과거 기록에 적용하거나 과거 정차 시각을 미래 시간표로 옮기지 않습니다.

초기 버전은 서버·DB·외부 관광 API 없이 동작합니다. iOS 앱 빌드와 스토어 출시는 별도의 macOS/Xcode 환경과 검증이 필요합니다.

## 역 좌표 검증

`scripts/station-locations.mjs`는 좌표와 주소의 시군구가 일치하는지 KOSTAT 경계로 확인합니다. 경계 단순화와 행정구역 개편을 고려해 4km 여유 및 청주 통합·군위 편입 등의 예외를 적용합니다. 경계 파일은 수집·검증 단계에서만 사용하고 브라우저에는 포함하지 않습니다. 출처와 이용 조건은 `scripts/data/README.md`에 기록했습니다.

ODCloud 원본에서 청량리와 철암의 좌표가 뒤바뀐 경우는 검토한 원본 값에 한해서만 교정합니다. 원본이 정상 좌표로 업데이트되면 이를 그대로 사용합니다. 주소와 충돌하는 좌표는 지도에서 제외하고 열차편·정차 순서에는 보존합니다. 배포 검증은 모든 표시 역의 주소 일관성도 검사하며 `coverage.json`에 교정 및 제외 내역을 기록합니다. 이는 역 위치의 검증이며 실제 철도 선형을 제공하는 기능은 아닙니다.

수집 후 `npm run data:resolve-locations`는 기존 Kakao JavaScript 키와 등록된 `http://127.0.0.1:5173` origin에서 장소검색 SDK를 실행해 누락 역을 보완합니다. Chrome/Chromium과 `playwright-core`가 필요하며 Actions에서 자동 실행합니다. 이름이 일치하는 기차역 분류의 결과만 사용하고, 주소·행정구역을 대조합니다. 멀리 떨어진 동일 이름의 후보가 여럿이면 확정하지 않습니다. 역 코드와 열차 정차 목록은 변경하지 않고 검증된 좌표·출처 ID를 배포 데이터에 저장하므로 방문자의 경로 검색마다 장소검색을 호출하지 않습니다.

지도에는 선택한 출발역과 도착역을 별도로 표시합니다. 위치를 확인하지 못한 끝점은 경고하며, 첫 번째로 표시할 수 있는 중간역을 출발역처럼 대체하지 않습니다.

## 지도 표시 성능

Kakao 지도의 `idle` 이벤트에서 화면 범위를 반영하고 표시할 역을 제한합니다. 이미 보이는 역의 오버레이는 재사용하며, 선택 상태 변경에는 스타일만 갱신합니다. 검색한 경로의 폴리라인은 역 오버레이와 별도로 관리합니다. 전국 운행 경로를 기본으로 모두 생성하거나 역을 선택할 때 전체 오버레이를 다시 만드는 방식으로 되돌리지 않아야 합니다.

추천은 현재 출발 도시를 제외하고 도착 도시별 한 곳만 제시합니다. 이동시간에는 탑승부터 도착까지의 환승 대기를 포함합니다. 추천 결과는 중간에 8곳에서 자르지 않고 조건에 맞는 도시 전체를 확인합니다. 도착 도시 검색과 페이지 이동으로 나머지 지역을 찾을 수 있고, 카드와 지도는 현재 페이지의 8곳만 표시합니다. 추천 계산은 Web Worker에서 실행하며 조건 변경·탭 이동 시 종료합니다. 지도에는 현재 페이지의 추천 역만 표시하고 경로는 카드를 선택한 뒤 그립니다. 추천도 표시된 날짜의 과거 기록에 한정되며 미래 운행·관광 명소·실시간 좌석을 보장하지 않습니다. 추가 API 키나 브라우저 공공데이터 요청은 필요하지 않습니다.

원자료의 `S수서`·`S동탄`·`S평택지제`는 화면에서 각각 `수서`·`동탄`·`평택지제`로 표시합니다. 원본 역명·역 ID·정차 목록은 유지하므로 이름 정리가 환승 가능 여부나 역 식별을 바꾸지 않습니다. SR 구분 역이 포함된 열차에서 운영사를 확정할 수 없으면 공식 차량 분류에 `차량`을 붙이고 코레일·SRT 예매를 함께 안내합니다. 선택한 구간에 구분 역이 없어도 전체 열차편의 정보를 유지합니다. `SRT`가 명시된 자료는 SRT 예매로 연결합니다. 열차번호만으로 운영사를 추측하지 않습니다.
